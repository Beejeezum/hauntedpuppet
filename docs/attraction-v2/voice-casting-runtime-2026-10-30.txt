RECOMMENDED ROUTE
1. Hear those short auditions beside the apology. Judge personality, thought,
   warmth/menace and consonant clarity. If none fit, write a custom Voice Design
   brief and generate one small comparison, not another generic preset library.
2. Keep a stable voice identifier for each form. Test a welcome, embarrassed
   recovery and threat using the same identities; verify delivery across lines.
3. For arbitrary typed lines, use a trusted server adapter. Runway's documented
   text-to-speech API accepts eleven_v3 and a runway-preset voice; the official
   Python SDK lists the Pip/Rachel/Monster/Grungle preset names. The connector's
   voice IDs must not be assumed to be portable ElevenLabs account voice IDs.
4. Runway generation is task-based. Its web workspace connector does not give the
   running app an API key or prove API billing shares the web-credit balance.
   Implement the job/cancel/error path before a private API connection. Never put
   a key into browser code or claim a static audition is a live integration.
5. If custom casting/response speed warrants a direct ElevenLabs account, its
   documented Voice Design flow returns previews; create the chosen preview as
   a saved voice, then request TTS against that voice ID. Streaming is documented
   separately. Verify current account/model support before selecting it.

FIRST LIVE ADAPTER CONTRACT
Input: bounded exact text (240characters), form and a server-side admitted voice
profile. Optional intent from a short allowlist: warm, conspiratorial, sheepish,
menacing. No arbitrary user-supplied provider/model/voice URL or SSML.
Output: bounded owned audio bytes, duration, actual provider/model/profile version,
generation timing and format; never expose provider API keys or long-lived asset URLs.
Cache key: exact text +form +model +voice identity +settings version. Bound cache
bytes/entry count; keep dialogue memory-only unless user explicitly saves a show cue.
Only one synthesis in flight per laptop queue. No automatic paid retry. A stop or
form change invalidates late completion and audio, even if provider billing already
occurred. Client disconnect should cancel/poll-stop where supported.
Reuse one AudioContext, retain the existing form hold and effects duck. Audio plays
only on the laptop; projector/phone get command/state and pictures, never speech ownership.
Replay saved audition audio without making another provider call.

TESTING
Fake transport: completed/failed jobs, rate limit, malformed duration/audio, timeout,
stale completion, Stop during wait/download/playback, bounded queue/cache, wrong-form
completion and audio context recovery. Exactly-zero paid calls in default tests.
Real opt-in: one short line per chosen voice. Measure click to first audible sample,
full generation time, playback duration and cancellation behavior. Advertised model
inference latency is not the app's end-to-end response time. Compare the returned
voice to the audition; do not treat HTTP200 or decoded PCM as creative acceptance.
No live mouth sync claim until coherent facial acting is actually integrated/tested.
