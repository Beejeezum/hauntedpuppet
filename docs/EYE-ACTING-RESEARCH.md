# Wisp's eyes: believable mechanics in a painted character

Primary sources checked October 15, 2026. Research and implementation proposal only: no dependency or application code added. The recommendation concerns our illustrated 2D ghost, not a conversion to a photoreal human face.

## Recommendation

Build a small **painted eye rig plus an attention controller** within the existing character renderer. Separate left/right iris movement, lid shape, blink, brow and highlight art; make them respond to a shared intended target. The biggest gain is intentional looking and coordinated anatomy, not higher-resolution iris textures. Preserve Wisp's approved large, appealing eyes.

The strongest knowledge reference is Disney Research's published [Realistic and Interactive Robot Gaze](https://la.disneyresearch.com/publication/realistic-and-interactive-robot-gaze/) and [paper](https://la.disneyresearch.com/wp-content/uploads/root.pdf). It describes layered alive/glance/engage behaviors and eyes reaching a target before the slower head. Its robot used brief movements among facial points while engaging a person. This is useful published evidence for behavior architecture, not a downloadable Disney production rig or a requirement to copy its robot's timings. Do not mistake an actuator's maximum frequency for a desirable random-eye-jitter rate.

For the anatomy/animation vocabulary, [Ruhland et al.'s eye-gaze review](https://www.scss.tcd.ie/Rachel.McDonnell/papers/CGF2015.pdf) distinguishes fixations, saccades, pursuit, eye/head coordination and vergence; it also discusses lids accompanying vertical eye movement. It is a literature synthesis, not a Wisp-specific calibration. Use these categories to art-direct behavior, rather than claiming biological accuracy from a sine wave.

## Mechanics to implement

These are proposed art-direction rules, not medical timing constants:

- **Fixate before moving again.** Pick a meaningful target and hold it. A listener should look attentive, not continuously scan.
- **Use brief saccades between holds.** Both eyes normally shift together. Small incidental offsets remain bounded and sparse; independently wandering pupils read as broken alignment.
- **Lead the head with the eyes.** On a large glance, eyes acquire first; head/body follow; eye offset then relaxes as the head catches up. Stabilize gaze during Wisp's own bobbing so the pupils do not slide randomly with the texture.
- **Couple lids to vertical gaze.** Looking down lowers the upper lid and changes the opening; looking up opens it within the design's limits. Use painted shape keys/cels or a bounded mesh, not translation of an unchanged oval. Let brows and cheek lift contribute to an actual smile.
- **Use vergence only when depth is meaningful.** Aim each eye from its own center at the same target. Clamp near convergence to avoid accidental crossed eyes. Without a calibrated visitor distance, use a gentle authored near/far cue, not an invented claim of measured depth.
- **Compose blinks.** A blink is a closure/reopening action, not an opacity fade. Make closed lids painted shapes. Suppress conflicting eye overlays during blinks and synchronize or deliberately offset lids for an expressive wink.
- **Keep highlights coherent.** A corneal-style glint should follow a consistent lighting model or painted placement; it should not move exactly like a sticker on the pupil. Avoid oversized wet human-eye reflections that fight the ghost's soft paint.

The controller should accept target position/depth, attention state, expression and an explicit operator override. Its output is bounded eye offsets, lid openness/shape, blink phase and delayed head target. Keep target selection separate from rendering so a future sensor does not rewrite the eye rig. Suggested states: idle curiosity, visitor listening, speaking, thinking glance, costume inspection and farewell. Tiny illustrative movements must remain visible at projection distance without constant twitching.

## Concrete production slice

1. Deliver one cute front eye study: clean face without baked-in eyes; separate sockets/sclera, iris/pupil, upper/lower lids, highlights, brows and closed-blink art. Supply front and three-quarter registration/occlusion rules. Keep replacement expression art consistent.
2. Approve a 15-second silent acting reel: notice visitor → look down at costume → back to face → listen → amused half-blink → farewell. Judge it close up and at intended street distance. Prefer this meaningful sequence over a reel of random eye motion.
3. Add one deterministic gaze controller and a clocked eye-pose contract shared with the silent projector. Directional back cels must hide the facial rig entirely; three-quarter views need their own allowable offsets/masks.
4. Test extreme gaze, full blink, view changes, overlapping expressions, long frame gaps, rapid operator overrides, Stop and Welcome kiddos. Assert pupils stay inside eye masks, lids cover them, poses remain finite, and no duplicate face appears. Acoustic mouth animation remains separate from gaze.
5. Record actual output and compare to the approved reel. Automated bounds/state tests cannot prove appealing eye contact. Calibrate to the projection's physical location: a single painted projection cannot independently make correct eye contact with every visitor standing at different angles.

Research sources provide capabilities and reference behaviors. The implementation rules and tool ranking above are project-specific engineering/art judgments. No proprietary rig, shader, sample character or third-party implementation was copied.

## Additional eye-specific GitHub studies

[lighttransport/procedural-eyeball-shader](https://github.com/lighttransport/procedural-eyeball-shader) is an actual GLSL iris/sclera experiment, rather than a general rendering engine. Its README labels it WIP and states MIT; the repository credits shader author FMS-Cat and a separate cubemap source. The reviewed root has no standalone LICENSE file. Treat it as a useful visual/technical study, not a production-ready complete eye rig; verify grant/attribution and cubemap rights before copying any implementation or resources. It supplies no eyelids, attention controller or painted Wisp identity.

[EyeSyn/EyeSynResource](https://github.com/EyeSyn/EyeSynResource) provides psychology-inspired gaze synthesis research artifacts, including a verbal-gaze model that uses weighted attention among facial landmarks. Its implementation is MATLAB, not a browser animation package. No clear repository-wide reuse license was established in this review, so use the paper as knowledge and obtain terms before reusing code/data. For Wisp, its useful lesson is context-dependent target selection and fixations, rather than continuous random pupil motion. No files from either project were copied.
