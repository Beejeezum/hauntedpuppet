# Whole-character Wisp performance candidates

These are generated animation sources, not recordings of people or guest conversations. They preserve a connected character as the benchmark against which interactive replacements must be judged. None is final approved production art.

The manifest records source session, hashes, roles and known failures. Originals are copied unchanged. The two cadence studies are explicitly derived offline; see the parent README for FFmpeg settings and evidence scope. Do not mistake48fps encoding for richer acting or target-hardware acceptance.

The comparison places the original on the left and the interpolation candidate on the right, synchronized at the same scale. Play with a video player capable of48fps. Scary/morph/return candidates retain known art problems. Speech tests v12–v14 failed readable articulation and remain outside this body-motion package.

Before live integration: obtain full-speed visual approval, resolve all-frame safe bounds in final display, preserve immediate Stop/Blackout and silent projector/phone, supply responsive facial performance without loose overlays, and test genuine voice and physical projection separately. Keep source/ excluded from the public build until an explicitly verified integration is ready.

## Reproducible local rehearsal

Serve the repository root with a static loopback server and open `source/wisp-performance-reference/runway-pilots/wisp-timed-speech-review.html`. Production server deliberately does not serve source/. Use `Play timed greeting`; audio defaults muted. This waits for mouth artwork and decoded body footage, performs the gesture and generated line, then returns to idle. Manual cues, Blackout and disposal stop the generated audio. No microphone, provider call or credentials are involved.

The mouth is still an experimental tracked patch with three coarse shapes, not an approved face rig. Automatic alignment does not establish phoneme accuracy. Video body acting is prerecorded, and this is not an implementation of native live conversation. Keep the source demo excluded from the public build.

## Human motion feedback

The user reports choppiness in the interpolated right-hand comparison when the hand overlaps fog. Treat that interpolation candidate as rejected for current use, regardless of its frame count or zero-drop decode test. The timed greeting source demo uses the original v8 footage; it does not load the interpolated candidate. Future interpolation tests must specifically review hand/fog occlusion before promotion.

The source rehearsal includes **Open silent rehearsal output**. This separate same-origin window mirrors the already composited canvas, including experimental mouth timing, without a second video/audio player. Blackout clears it immediately; Escape stops that output; owner disposal clears and retires it. This is a local rehearsal path, not integration with the production phone/projector protocol, not measured end-to-end display latency, and not physical projection acceptance.
